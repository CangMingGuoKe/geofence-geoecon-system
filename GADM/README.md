# 全球地理围栏四层体系 · 交互地图

深圳数据经济研究院 · 卫星遥感数据研究中心

**在线地图**：https://cangmingguoke.github.io/geofence-geoecon-system/

## 项目简介

一套 **国家 / 省州 / 市郡 / 区县** 四级行政区划地理围栏数据体系，覆盖近五年名义 GDP 前 20 国。本仓库面向公众展示项目产出与交互地图；完整边界数据（GeoJSON / GeoPackage）与构建脚本因 GADM 许可（禁止再分发）保留在院内本地。

## 研究背景与用途

本体系服务于卫星遥感与数据经济的交叉研究。卫星遥感观测（夜间灯光、土地利用、企业点位等）以经纬度 / 像元为载体，而经济金融数据（GDP、企业注册、人口等）以行政区划为口径，两者"天-地"分离。地理围栏即连接二者的**空间桥梁**：

- **点 → 行政区空间匹配**：任意经纬度（遥感像元、POI、企业点位）可快速落到国家 / 省州 / 市郡 / 区县四层，返回统一 GID 编码（R-tree 空间索引，点-多边形 O(log n)）。
- **遥感指标行政聚合**：把栅格遥感观测按行政边界聚合为省州 / 市郡 / 区县级指标，作为经济活动与城市化进程的空间代理变量。
- **跨尺度口径统一**：以同一套四层 GID 编码对齐多来源、多分辨率数据，支撑面板回归、空间计量等下游分析。

## 功能特性

- **四级行政区划**：L1 国家 → L2 省/州 → L3 市/郡 → L4 区县，跨国家命名一致、编码唯一。
- **交互地图**：大洲/国家切换、L1-L4 层级缩放、城市中英文标注切换、滚轮缩放/拖拽平移、悬停显示区县名。
- **搜索高亮**：中文、拼音均可检索；按唯一 GID 定位，避免同音歧义（如台州 / 泰州均拼 Taizhou）。
- **双格式交付**：GeoJSON（国家 × 层级）+ GeoPackage（每国一个、含四层图层）。
- **点匹配接口**：`match_points` 把经纬度批量匹配到四层行政区（本地脚本提供）。

## 字段字典

四层行政层级统一映射到 GADM：

| 层级 | 名称 | GADM 层级 |
|---|---|---|
| L1 | 国家 | ADM0 |
| L2 | 省/州 | ADM1 |
| L3 | 市 / 郡 | ADM2 |
| L4 | 区县 | ADM3 |

每个要素保留 GADM 原始字段，并额外写入两个层级字段：

- `GID_N`：第 N 级唯一编码（如 `FRA.1.1_1`），本体系的空间主键
- `NAME_N` / `NL_NAME_N`：第 N 级英文名 / 本地名
- `TYPE_N` / `ENGTYPE_N`：本地 / 英文行政类型名
- `level`：本体系层级 1-4；`admin_level`：对应 GADM 层级 0-3
- `geometry`：Polygon / MultiPolygon（统一 WGS84 / EPSG:4326）

> 部分国家有更深层级（如法国公社 ADM4）已按四层规范舍弃；不足四层的小国缺失层不产出文件。

## 唯一键与重名消歧（技术要点）

GADM 在同一层级内**文本重名非常普遍**，所以**名字不能当主键**。美国 L3 层 3,148 个县里只有 1,839 个名字不重复，剩下 442 个名字被用在不止一个县上，最多的是 Washington，31 个县都叫这个名字。程序如果按名字认地方，这 31 个会被当成同一个。各国 L3（ADM2）实测：

| 国家 | L3 要素数 | 不重复名数 | 重名个数 | 最重复的名字 |
|---|---|---|---|---|
| 美国 | 3,148 | 1,839 | 442 | Washington ×31、Jefferson ×26、Franklin ×25、Jackson ×24、Lincoln ×24、Madison ×20 |
| 日本 | 1,811 | 1,673 | 109 | Misato ×6、Asahi ×5、Mihama ×4 |
| 印度 | 676 | 659 | 16 | Kinnaur ×3、Anjaw ×2 |
| 中国 | 390 | 380 | 8 | Yulin ×3、Ngari ×3、Suzhou ×2 |
| 德国 | 403 | 403 | 0 | 无 |
| 法国 | 96 | 96 | 0 | 无 |

处理规则，逐条：

1. **空间主键一律用 `GID_N`**（如 `USA.47.40_1`），它是全库唯一编码。`NAME_N` 只用于显示；任何按名筛选、按名连接、按名去重的操作，都可能把两个不同地方混成一个。每条下级记录里还带着指向上级的外键（`GID_1`、`GID_2`），要上级信息顺着外键取就行。
2. **`HASC_N` 不能当主键。** GADM 的 HASC 由名称推导，同名即同码。美国 L3 层共 **8 组 HASC 撞码**：`US.VA.FC` 同时属于 Fairfax 县与 Fairfax 市，`US.VA.RO` 属于 Roanoke 县与 Roanoke 市，`US.VA.BD` 属于 Bedford 县与 Bedford 市；另 5 组是水体与县相撞（`US.IL.WB` = LakeMichigan 水体 + Wabash 县，`US.IN.WB`、`US.MN.WB`、`US.WI.WB`、`US.MI.WB` 同理）。
3. **中文名按 `GID` 精确取 `NL_NAME_N`**，不要用英文名反查。中国层尤其如此：台州与泰州同为 `Taizhou`、苏州与宿州同为 `Suzhou`、福州与抚州同为 `Fuzhou`、伊春与宜春同为 `Yichun`，英文名反查必然出错。`NL_NAME` 形如 `江蘇|江苏`，取 `|` 分隔的简体段。
4. **水体要素须显式剔除。** 美国 L3 层含 11 个 `TYPE_2 = Waterbody` 的五大湖水体要素，它们不是县。真县等价单元 = 3,148 − 11 = **3,137**。（注意：11 是**水体要素数**；上文 HASC 撞码里的「5 组水体与县相撞」是**共用同一 HASC 码的组数**，两者不是一回事。）

**中国区县层的同省同名。** `docs/audit_summary.txt` 记为 **132 组**；按 `docs/audit_detail.csv` 的「省 + 县名」组合、以**原始字符串**统计为 **115 组**。两个数字都对，差在口径：审计汇总用的是**归一化后**的「省名 + 县名」（繁转简、去行政后缀、合并括注，见 `scripts/audit_china_l4.py` 的 `norm_name`），归一化会把「河北」与「河北省」这类写法并成一个键，从而多出一些重复组；用审计脚本自己的 `norm_name` 复算即为 **132 组**。最集中的是重庆「省直辖县级行政区」32 个、澳门「澳门特别行政区」8 个、河北「保定市」6 个、内蒙古「呼伦贝尔市」5 个。这些是 GADM 原始数据的名字缺失或笼统标注所致，已按民政部代码表定向纠名。



## 构建流程

1. 从 GADM 4.1 下载近五年 GDP 前 20 国按层级行政区划（原始数据保留在本地 `raw/`）。
2. 标准化：统一 WGS84 / EPSG:4326，写入 `level`、`admin_level` 字段。
3. 按 L1-L4 分层输出 **GeoJSON**（国家 × 层级）与 **GeoPackage**（每国一个、含四层图层）。
4. **台湾作为省级单元并入中国**，中印争议区保留并归属新疆/西藏。
5. 中国区县（L4）用民政部 GB/T 2260 做一轮全国审计与批量修复（见下）。
6. 生成交互地图并部署到 GitHub Pages。

**地图数据精度**：`map_data/*.js` 存的是**简化后**的几何（`build_interactive_map.py` 里 `SIMPLIFY = 0.002` 度，约 220 米），只用于页面展示与点选，**不要拿去算面积**；精确边界以 `gpkg/` 下的 GeoPackage 为准。

## 中国数据（重要）

**领土完整性**：已按中国官方主张处理，不遗漏任何一寸领土：

- 台湾作为省级单元并入中国（含 22 县市；台湾 GADM 只到县市层，乡镇级 L4 无数据，交互地图 L4 视图下以县市呈现、不留白）。
- 澳门 8 个堂区统一标注"澳门特别行政区"。
- 中印争议区（阿克赛钦、班公错等）保留并归属新疆/西藏，未删减。

**区县（L4）修复审计**：GADM 原始中国区县层存在全国性「名字贴错多边形 / 空名」问题，已用民政部县级区划代码（GB/T 2260）作真值做了一轮审计 + 批量修复：

- **已确定性修正 444 处**：区县改名/纠错 48、行政区划调整 11、市辖区重标核心 55、空名补齐 285、定向纠名 37、同步修正 8。例如张家港（GADM 记旧名"沙洲"）被误并入苏州、重庆 31 区县被笼统标作"省直辖县级行政区"，均已改回真实县名。
- **仍存问题（无法用 GADM 几何定案，已记录于本地 `docs/unfixed.txt`）**：约 19 处"名字贴错多边形"、约 894 处区县缺失（约 14%，多为市中心区）、核心市区被合并成单个"市名"面。
- **结论**：省（L2）、市（L3）两层相对可靠；区县（L4）经校正后仍仅供粗略参考。**涉及中国的地图不可用 GADM 出正式出版图**；精确的中国区县边界请改用自然资源部标准地图（带审图号）或民政部行政区划数据。

## 已知几何与属性缺陷（美国层）

美国存在「县」与「独立市」同名的建制（弗吉尼亚等州）。GADM 对这两种情形处理**不一致**：

- **拆开的情形**：Fairfax 县与 Fairfax 市、Roanoke 县与 Roanoke 市、Bedford 县与 Bedford 市各有独立要素，但两者共用同一个 `HASC_2` 码（见上节）。
- **合并的情形**：巴尔的摩市（Baltimore City，FIPS 24510）与圣路易斯市（St. Louis City，FIPS 29510）**没有独立要素**，其辖区被并入同名县多边形。

**合并情形的实测证据**：

| GADM 要素 | GID_2 | GADM 面积 | 对照 |
|---|---|---|---|
| Baltimore（马里兰州，County） | `USA.21.3_1` | 1,794 km² | 巴尔的摩县陆地 1,549 + 巴尔的摩市陆地 210 ≈ 1,759 km²（+2%） |
| SaintLouis（密苏里州，County） | `USA.26.95_1` | 1,516 km² | 圣路易斯县陆地 1,315 + 圣路易斯市陆地 160 ≈ 1,475 km²（+3%） |

把两市质心（巴尔的摩 -76.6108, 39.2904；圣路易斯 -90.1994, 38.6270）投到对应多边形，均**落在内部**，而非落在孔洞里。

**结论：这两个市在 GADM 里既不是「缺失几何」，也不是「围栏空洞」**，而是「面积被并入同名县、无法单独归属」。任何按县汇总的下游指标，其分母会静默包含这两个市的面积与人口。

> 附：都市圈并集多边形里出现的「孔洞」全部是并集 + 简化产生的**零面积缝隙**，不是真实空洞。实测 USM01 的 41 个孔、USM02 的 4 个孔、USM23 的 38 个孔，面积均为 0.00000 平方度量级。

## 检索与标注的消歧实现

交互地图的检索与标注依赖三份产物：`map_data/_search.js`（全局检索索引）、`map_data/{ISO3}.js`（各国几何与名称）、`interactive_map.html`（渲染与交互）。本轮修掉了展示层的两处重名缺陷，下面记录这两处缺陷与修法。

### 一、两处缺陷

1. **检索下拉无法区分同名条目。** 索引条目只带 `gid / en / loc / zh / iso3 / lv`，没有父级信息，下拉副标题只显示「国家 · L层级」。全库 **4,038 组**同名条目在下拉里长得完全一样（`Merkez` ×73、`Washington` ×32、`Jungang` ×31），必须点开才知道选中的是哪一个。选中本身没有错（点选后按 `gid` 定位与高亮），错的是**候选列表无法辨认**。
2. **省级译名被套到县级要素上。** 中文词典按「名称」建键、不分层级，同一个名字在 L2 是省、在 L3 可能是同名的县。实测 L3/L4 层有 **176 条**中文名以「州 / 省 / 自治区 / 地区 / 道」结尾，最典型的是 31 个 Washington 县被显示成「华盛顿州」。

### 二、修复实现

**1. 给检索条目加「上级」字段 `p`**

`extract_country()` 顺带产出 `parent_map`：`{子级 GID: (父级 GID, 父级本地名)}`，取自 GADM 行自带的祖先字段 `GID_{level-2}` 与 `NAME_{level-2}`（ADM2 行带 `GID_1` / `NAME_1`，ADM3 行带 `GID_2` / `NAME_2`）。

`main()` 再建一份「GID → 显示名」索引 `disp`（优先中文名，退回本地名），以及它的去版本后缀版本 `disp_base`。检索条目新增 `p`，仅对 L3 / L4 写入（L2 的上级就是国家，不重复）。取值三级兜底：

```
上级显示名 = disp[父级 GID] 或 disp_base[去版本后缀(父级 GID)] 或 父级本地名 或 ""
```

前端 `renderSearch()` 的副标题由「国家 · L层级」改为「国家 · 上级 · L层级」；`searchMatch()` 的排序键追加 `p`，使同名条目在列表中成组相邻，一眼可辨。`t=3`（经济都市圈）走独立分支，不受影响；`USA_metro.js` 由 `09_生成经济图层.py` 单独生成，本轮未改动。

**2. 按层级约束中文译名**

只有**同时满足两条**，才判定为「省级译名误套」，把中文名置空（界面回退显示英文 / 本地名）：

1. 该名确实是本国的一个省名（L2 层的 `NAME_1` 集合里有它）；
2. 词典给出的译名带省级后缀（`州 | 省 | 自治区 | 特别行政区 | 大区 | 地区 | 道`）。

这两条都必要：只按「同名」判定会误伤「吉林市」「北京」这类本身正确的译名（它们就在同名省份内部，或本身就是省级兼市级）；不加后缀条件则连日本「山形」、瑞士「沙夫豪森」这种不带后缀、本身没错的译名也会被清掉。反过来，美国、墨西哥、沙特都有「同名省内还有同名下级单元」的情形（纽约州里有 New York County、奇瓦瓦州里有奇瓦瓦市镇、塔布克省里有塔布克省辖区），不能因为父级同名就放过。

整条规则**只作用于词典路径**（条件 `not f.get("zh")`）。中国走 GADM 自带的 `NL_NAME`，按 GID 精确取值，不存在跨层级串味，所以「和田地区」「阿坝藏族羌族自治州」等 77 条县级以上正确译名正靠这条保住。

### 三、两个需要留意的地方

- **父级 GID 不能用字符串截断推导。** GADM 的 `_N` 后缀是**版本号**，父子两层并不一致：巴西的 `BRA.1.1_2` 其父级是 `BRA.1_1` 而不是 `BRA.1_2`，按截断推导会大面积错配。必须读行自带的祖先字段 `GID_{level-2}`。
- **个别国家的父层记录属性全空，父级 GID 在父层查不到。** 全库 L3 有 **73 / 20,532（0.36%）**、L4 有 **71 / 37,381（0.19%）** 取不到父级。根因是 GADM 数据瑕疵：荷兰 `NLD.14_1`（实为 Zuid-Holland 省）的 `NAME_1 / TYPE_1 / ENGTYPE_1` **全部为 NA**，被本仓库 `clean_gdf` 按「名称与类型全缺的垃圾要素」剔除，于是 53 个荷兰市镇引用的父级凭空消失；英国则是子行 `GID_1` 直接写成字符串 `"NA"`。靠「精确 GID → 去版本后缀 → **子行自带的父级本地名**」三级兜底补回（GADM 会把祖先名反规范化写进子行），覆盖率 **99.98%**，剩 9 条英国要素留空。

### 五、复现与校验

`scripts/build_interactive_map.py` 是**唯一真源**：`interactive_map.html`、`index.html` 与脚本内的 HTML 模板三者**字节一致**（同一 md5，改动前已核对），因此只改脚本、重跑构建即可，不会出现「手改了 HTML、下次重跑被覆盖」的问题。

```bash
cd GADM
python scripts/build_interactive_map.py     # 重新生成全部 map_data/*.js + interactive_map.html
cp interactive_map.html index.html          # 两份 HTML 保持字节一致
```

校验要点：

- 重跑后各国 `map_data/{ISO3}.js` **字节不变**（本轮实测无差异），只有 `_search.js` 与两份 HTML 变化。这说明构建是确定性的，改动可审计。
- 抽查同名项：检索 `Washington` 应返回 1 个州 + 31 个县，每个县副标题显示各自的州。
- 抽查译名：`和田地区`（中国，应保留）；`New York County`（中文名应已清空、回退英文，不再显示「纽约州」）。
