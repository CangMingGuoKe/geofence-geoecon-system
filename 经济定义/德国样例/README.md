# 德国 OECD FUA 市镇拼合与匹配修复 v2

数据构建日期：2026-10-15；仓库整理日期：2026-10-22。用途：按 OECD 城市功能区（FUA）成员定义建立可追溯的德国区域边界候选，为后续经济指标与遥感数据的空间对齐提供基础。全部结果待研究团队复核。

**成员覆盖问题已有可执行的修复结果；经济数据与最终边界的定义年份一致性尚未证实。** 本版不能直接宣称是已验收的科研边界或历史年份边界。

## 结果

| 指标 | 第一版 | 第二版 |
|---|---:|---:|
| OECD 成员记录 | 4,323 | 4,323 |
| 成功匹配成员 | 1,626（名称规则匹配） | 4,320（官方编码精确匹配） |
| 直接匹配率 | 37.61% | 99.93% |
| 底图 | GADM 4.1 ADM3，行政粒度不统一 | GISCO 2024 LAU，市镇粒度 |
| 有效非空 FUA 几何 | 97 | 98 |

第二版另有 3 条旧成员通过官方行政合并记录追溯到同一 FUA 内已存在的后继市镇。于是 4,323 条记录都能在 2024 口径下说明几何去向，但这不等于有 4,323 个独立市镇面，也不等于恢复了合并前的历史边界。严格匹配版仍如实保留 3 条 unresolved_code。

本版采用了“官方市镇编码连接、官方市镇边界替代混合粒度底图、行政合并证据、独立参考边界对照”四步。没有增加模糊匹配来凑成功率。没有建立或声称建立 BKG AGS/ARS 到 GADM GID 的官方桥表。BKG 下载入口返回拒绝访问后，改用 GISCO 的官方德国市镇层。

## 先看哪些文件

1. `outputs/16_官方市镇拼合与FUA参考.png`：柏林与鲁尔区的市镇拼合和官方 FUA 参考对照（不含 GADM 几何）。
2. `outputs/09_成员追溯与2024边界对应.csv`：4,323 条成员的编码、匹配方法与合并去向，是追溯主表。
3. `outputs/10_德国FUA_2024口径边界.geojson` 或同名 `.gpkg`：98 个候选 FUA，可在 QGIS 打开；坐标为 WGS84（EPSG:4326），面积用 EPSG:3035 平面计算。
4. `outputs/11_与GISCO官方FUA空间比较.csv`：79 个同码参考区域的交并比、差异面积、参考名称；19 个缺失参考保留为空。
5. `outputs/12_需复核的FUA.csv`、`14_市镇层面参考边界差异.csv`、`15_同码名称差异分类.csv`：定位剩余问题。
6. `outputs/verification.json`：已通过的技术验证；`quality_summary.json`：机器可读的汇总。

`07_德国FUA_官方市镇拼合_v2.geojson` 是严格编码匹配版；`10_德国FUA_2024口径边界.geojson` 增加历史合并的追溯属性。由于后继市镇本来就已在相应 FUA 内，两版几何相同，覆盖解释不同。不要将前者的 unresolved 数与后者的追溯覆盖混用。

## 三个历史编码如何处理

| 旧成员编码 | 原名称 | 后继编码 | 生效日期 |
|---|---|---|---|
| 01059101 | Tastrup | 01059126 Hürup | 2023-03-01 |
| 01059141 | Maasbüll | 01059126 Hürup | 2023-03-01 |
| 16076026 | Hartmannsdorf | 16076003 Bad Köstritz | 2023-01-01 |

Hürup 在 Flensburg FUA（DE049F）中，Bad Köstritz 在 Gera FUA（DE113F）中。程序验证后继编码已精确匹配且与旧成员属于同一 FUA，保留旧行并记录 `geometry_ags`，不重复添加后继几何。具体官方证据在 `08_历史行政合并证据.csv`。这种处理只适用于本次已核实的三个案例，不能推广为“所有旧编码都可用整块新市镇代替”。

## 仍需处理的科研口径问题

官方 GISCO FUA 并非本次 OECD 成员定义的已证实等价物。79 个可比较区域的 IoU（交集面积 / 并集面积）中位数为 88.64%；8 个达到 98% 的诊断阈值，71 个低于阈值，另 19 个没有同码参考。98% 只是复核排序规则，不是科研验收标准，也不能据此认定低于阈值的 OECD 成员表有错。

- 柏林：成员从 71/118 提升至 118/118，与参考 IoU 从 76.32% 提升至 96.60%。成员覆盖明显改善，但仍有参考范围差异。
- 科隆：原来就已 28/28 成员匹配，第二版与参考 IoU 约 84.54%。可见完整匹配与区域定义一致是两个不同问题。
- 鲁尔区：OECD `DE006F` 名称为 Ruhrgebiet，GISCO 同码名称为 Essen，第二版与参考 IoU 约 30.75%。不能把整个鲁尔区的经济值直接配到 Essen 参考范围。

两套边界的源定义、边界年份及概化尺度（LAU 01M 与 FUA 100K）均可能影响差异，尚未逐项归因。比较来自单独发布的官方 FUA 文件，不是用同一成员表再生成一遍；但市镇与 FUA 参考同属 GISCO，因此也不是完全独立的测绘验证。没有为了贴合参考而自动改动 OECD 成员归属。

1,061 条编码匹配存在名称写法差异，其中 1,028 条可用逗号前名称相同解释，另 33 条保留为其他名称差异。此分类只是人工复核提示，不证明历史范围没有变化。602 条成员的 2024 几何有超过一半面积在同码参考 FUA 外，详见市镇差异表；合并前成员共享后继几何，逐行计数不等于独立市镇计数。

下一步应以实际使用的 OECD GDP/其他指标的数据集元数据确认 FUA 定义及适用年份，并取得相同版本的 OECD 原生边界或成员定义说明。当前 OECD 官网 FUA ZIP 返回 HTTP 403，尚未验证 OECD 原生边界。2024 底图不能自动当作 2018—2022 年 GDP 的历史边界。当前文件足以开展团队复核与开发试验，尚不足以证明可直接用于论文的最终空间统计。

## 主要字段

| 字段 | 含义 |
|---|---|
| pk / member_ags | OECD 原成员标识 / 去掉 DEU 前缀后的 8 位德国编码；必须按文本读取，保留开头 0 |
| fuacode / fua_code | OECD FUA 编码；不同数据源同码不保证定义等价 |
| official_lau_id | 从 GISCO_ID 的 DE_ 前缀后提取的 8 位市镇编码 |
| match_status | exact_code 或 unresolved_code；严格直接连接的结果 |
| coverage_method | exact_code 或 documented_merger_into_existing_member |
| geometry_ags | 实际表示该成员的 2024 市镇几何编码；历史合并前成员可共享该编码 |
| members_matched | 直接编码匹配的成员数，不包括合并前成员 |
| members_accounted_2024 | 按本次有证据的合并追溯后可说明去向的成员数 |
| distinct_geometry_units | FUA 实际使用的不同市镇几何数量，避免合并记录重复计面 |
| v2_iou | 与同码 GISCO 参考范围的交并比；无参考为空，不是 0 |
| flag / review_status | 诊断提示 / pending；不存在自动“人工审核通过” |

CSV 为 UTF-8 BOM。使用 Excel 导入时将编码列指定为文本，防止前导零丢失。面积为平方公里，比例为 0—1；空值表示缺少参考或未计算。GeoPackage 中 `attributes_json` 保存完整 FUA 属性。

## 可复现与技术验证

仓库包含结果、逐成员第一版匹配记录及 sources.json 来源/时间/SHA256。原始下载按仓库约定只在本地缓存，首次重建需要联网；之后可使用通过哈希校验的本地缓存。建议 Python 3.11 或更新版本：

```powershell
python -m pip install -r requirements.txt
python run_all.py
```

脚本先运行 prepare_data.py，从 sources.json 获取指定版本的 OECD/GISCO 文件并核对 SHA256，再重建 outputs。已存在且校验正确的缓存不重复下载。若官网文件变化或下线，脚本停止并提示，避免静默更换数据版本。原始缓存被 .gitignore 排除。第一版空间 IoU 使用 raw/v1_spatial_summary.csv 中的历史计算快照，本仓库不能重新验证第一版 GADM 几何；第二版与参考的空间指标则重新计算。预览采用可回退的字体，不影响数据计算。

已检查：所有已下载原始文件的来源哈希、4323 条成员和唯一标识、三个合并关系与同一 FUA 条件、98 个非空有效面、柏林从原始 SHP 按 118 个编码独立重建、GeoPackage 数据库完整性与 98 个几何往返、79 个 IoU 的范围与 19 个参考缺失。第一版原计算曾对投影后的比较副本使用 make_valid；本次发布重建仅载入历史 IoU 快照，不处理第一版几何。`11_空间比较用几何修复.csv` 记录本次重建实际发生的修复。第二版源面未需要几何修复。这些是技术验证，不构成人工地理审核。

第一版逐成员结果和空间指标快照保存在 raw，用于对照；第一版 GADM 几何和原始底图仅留本地。没有修改 GitHub 仓库或生产地图。若团队坚持全部采用 GADM，本版应作为补充底图方案和问题诊断，不能将 GISCO 几何伪装成 GADM GID。
