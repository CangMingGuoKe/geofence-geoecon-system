# 步骤 9 · 阶段演示说明（经济都市圈图层 · 集成进现有产品）

> 深圳数据经济研究院 · 卫星遥感数据研究中心 · 美国经济定义样例
> 日期：2026-09-11

## 定位：集成进现有产品地图（纯增量、可回退）

经你指出「独立 Leaflet 演示与产品雏形八竿子打不着、风格全变了」，步骤 9 改为**把经济都市圈图层直接集成进现有产品地图**，而非另起炉灶。

现有产品是**自研 Canvas 矢量渲染器**（非 Leaflet）：墨卡托 `mercY` 手投 + `view={s,ox,oy,w,h}` 平移缩放 + `pointInPoly` 命中 + `evenodd` 孔洞填充，蓝衬线设计（`--accent:#3b7cb8` 等）。集成完全沿用这套渲染与交互约定，只**新增**数据文件与开关，不改动原有行政边界 / 城市标注 / 搜索逻辑。

## 集成方式（零侵入）

| 文件 | 变更 |
|---|---|
| `map_data/USA_metro.js` | **新增**。`window.USA_METRO`（88 都市圈）+ `window.USA_METRO_SEARCH`（88 搜索项），原始经纬度 + JS 端墨卡托投影（对齐现有 `map_data/*.js` 约定） |
| `interactive_map.html` | **增量**：经济都市圈开关行、canvas 图层叠加、悬停 tooltip、点选详情卡、搜索 t=3 分支、`preprojectMetro` / `hitTestMetro` / `renderMetroDetail` 等函数 |
| `index.html` | 与 interactive_map.html 保持字节一致（同步副本） |
| `scripts/build_interactive_map.py` | HTML 模板字符串同步同样改动（避免重跑构建时覆盖） |

改前已备份至 `_metro_备份_20260911/`；仓库树原本干净，`git restore` 可整体回退。

## 数据来源

- 都市圈边界：`07_美国都市圈边界.geojson`（union 几何，简化 0.005° ≈ 550m）
- 匹配 / 审核状态：`08_审核状态.csv` + `08_版本记录.csv`
- 生成脚本：`09_生成经济图层.py`

## 演示功能

| 目标 | 实现 |
|---|---|
| 图层开关 | 控制面板新增「经济都市圈」开关（当时仅美国可选；切到其他国家自动关闭并置灰） |
| 图层叠加 | 完整都市圈蓝色半透明填充，**有缺失成员的都市圈橙色**（Baltimore USM02、St. Louis USM23） |
| 搜索 | 现有搜索框已接入，输入都市圈名（如 Atlanta / Baltimore）可直达并弹出详情 |
| 点选详情 | 点击都市圈 → 下方详情卡列出成员县（名称 / 所属州 / 匹配方法 / 审核状态） |
| 审核状态 | 详情卡显示 CBSA、成员数、匹配 / 缺失数、审核版本号与最近动作 |

## 补记（2026-09-29）：日本图层已接入

日本经济定义层建成后，经济都市圈开关不再写死美国：改为按国家判断，只要该国挂载了 `<ISO3>_METRO` 数据就可用。现在美国与日本都可用，切到其他国家仍会自动关闭并置灰。判别逻辑从 `country !== 'USA'` 改成 `!hasMetro(country)`；检索命中都市圈时会先切到它所属的国家（原先前者写死美国，跨国检索会串）。

日本样例的产物在 `经济定义/日本样例/`，图层数据是 `GADM/map_data/JPN_metro.js`。
